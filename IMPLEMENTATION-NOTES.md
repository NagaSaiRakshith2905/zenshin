## Phase 3 — Authentication, ownership and agent credentials — 2026-10-29

Built GitHub-only Better Auth/Drizzle login, explicit first-owner provisioning, closed implicit signup, secure HttpOnly SameSite=Lax sessions on HTTPS, encrypted provider tokens, database-backed auth throttling, protected workspace pages and owner-only preference/credential services and versioned routes. `OWNER_GITHUB_ID` is required validated environment configuration; provider identity and stored binding are checked independently of login name/email. A stable generated-compatible `github:<id>` user ID prevents duplicate owners under concurrent first callbacks. Only the necessary public auth routes are exposed; OAuth state/callback handling and standard CSRF/origin protections remain enabled.

Added human/agent/system actor types and project/scope checks. Bearer verification uses the key plugin with session conversion disabled, then reads current server-owned policy/grants and key state without a permission cache. Settings reject bearer/API-key headers even alongside owner cookies. Key creation, policy and explicit project grants commit together; edits check revisions, revocation disables the plugin key atomically, and arbitrary plugin metadata/permission labels never confer domain authority. Read only grants read; Contributor grants read/write/upload; archive/complete are independent opt-ins. Expiry defaults to 90 days, with custom 1–3650-day or explicit no-expiry choices. Forward migrations retain non-secret expiry/revocation/last-use history after plugin cleanup and add its generated auth rate-limit table/defaults. Plugin hashes/verification/expiry remain authoritative. Migrations were generated offline, not applied.
